Pre-quantum cryptography in Ethereum mainnet contracts

If user accounts become post-quantum but the contracts they rely on keep checking ECDSA, elliptic-curve or RSA signatures and proofs, what still depends on pre-quantum cryptography? How many contracts, can they change, do they have an alternative path, and how much value goes through them?

5 · How user signatures are checked

For a new PQ account, what matters is whether an ERC-1271 path exists. For a migrated EOA that keeps its address, the risk is any path where the old ECDSA key still works. EIP-8151 addresses that by making ecrecover fail for accounts with real code.

6 · Token supply behind permit

Market cap of tokens whose permit was used in the year, coloured by whether the permit path has a non-ECDSA option. Immutable ECDSA-only tokens can only be protected at the protocol level (EIP-8151).

7 · Rollups whose L1 contracts verify pre-quantum proofs

L2BEAT value secured, by state-validation type. SNARK verifiers on L1 use BN254 pairings; blob rollups also depend on KZG commitments. "Canonical" is value escrowed on L1.

8 · Lattice verifiers on mainnet

Found by scanning 2.48M unique runtime bytecodes deployed since block 18M for Falcon and ML-DSA NTT tables. Six exist; together they have about 13 calls and dust balances.

Method and caveats

  • Detection: every successful precompile call on mainnet from a geth callTracer trace (precompile-tracer). The caller is the execution context: the proxy for proxies, the EOA for 7702 delegations. Contracts that verify ECDSA in pure Solidity, or weren't called in the window, are missed.
  • Tx value: the largest single ERC-20/ETH transfer in each transaction, summed over distinct transactions. Estimated from a 1-in-10 block sample of Xatu transfer tables, priced with DefiLlama (99.2% of transfers priced). Groups can overlap. Bridge value is understated, because attestation and transfer usually happen in separate transactions.
  • Held: ETH plus the first 50 ERC-20s held now, fetched for the ≈3.9k most important addresses.
  • Classification: account vs application and immutable vs upgradeable come from rules for the long tail (selectors, proxy slots, names). The 433 largest contracts were classified by reading verified source or bytecode; 65 are low confidence.
  • Lattice: static bytecode scan (Falcon / ML-DSA twiddle and zeta tables), confirmed by hand.
